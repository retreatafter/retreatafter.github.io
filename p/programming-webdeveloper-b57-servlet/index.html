1.概述

  • (1)Servlet是Java语言编写的服务器程序，按照Servlet规范开发，用于做视图层（表现层/表示层）开发实现动态Web（不同人看到不同页面），本质是一个接口，需要依赖服务器（例如Tomcat）才能运行。
    • Tomcat才是与客户端直接打交道的家伙，它监听了端口，请求过来后，根据url等信息，确定要将请求交给哪个servlet去处理，然后调用哪个servlet的service方法，service方法返回一个response对象，tomcat再把这个response返回给客户端。
  • (2)现在看来，Servlet的应用方式很原始、繁琐了，后续用框架会逐步简化，但底层逻辑是不变的。

  • (1)开发Servlet有三种方法，Servlet的发展是一步步的，最终简化为Httpservlet类：
    • 1)实现Servlet接口。Servlet类是Servlet体系根接口。
    • 2)继承GenericServlet类。GenericServlet类是Sservlet抽象实现类。
    • 3)继承Httpservlet类。Httpservlet类，继承GenericServlet类，是对HTTP协议封装的Servlet实现类。

  • (3)Servlet生命周期，Servlet运行在Servlet容器即web服务器中，其生命周期由容器web服务器来管理，分为4个阶段：
    • 1)加载和实例化：默认情况下，当Servlet第一次被访问时，由容器创建Servlet对象，即Web服务器（这里是Tomcat）负责创建Servlet对象。
    • 2)初始化：在Servlet实例化之后，容器将调用Servlet的init()方法初始化这个对象，完成一些如加载配置文件、创建连接等初始化的工作。该方法默认只调用一次。
    • 3)请求处理：每次请求Servlet时，Servlet容器都会调用Servlet的service()方法对请求进行处理。
    • 4)服务终止：当需要释放内存或者容器（服务器）关闭时，容器就会调用Servlet实例的destroy()方法完成资源的释放。在destroy()方法调用之后，容器会释放这个Servlet实例，该实例随后会被Java的垃圾收集器所回收。

import javax.servlet.*;
import java.io.IOException

public class HelloHttp extends HttpServlet {
    // get和post只是请求实现的不同的方式，可以相互调用，业务逻辑相同，因此我们只需要写其中一个，另外一个往上调用即可
    //处理get请求
    //req用于获取客户端信息，res用于向客户端返回信息
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        PrintWriter writer = resp.getWriter();  // 字节流，响应流
        writer.print("Hello,Serlvet"); //这是在客户端（浏览器）上打印
    }

    //处理post请求
    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        this.doGet(req, resp); //形参收到后就调用doGet()方法
    }
}

package com.github.servlet;

import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.io.PrintWriter;

//若使用注解方式配置映射 @WebServlet(urlPatterns = "/*")
public class HelloServlet extends HttpServlet {
    // get和post只是请求实现的不同的方式，可以相互调用，业务逻辑相同，因此我们只需要写其中一个，另外一个往上调用即可
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
//        ServletOutputStream outputStream = resp.getOutputStream();
        PrintWriter writer = resp.getWriter();  // 字节流，响应流
        writer.print("Hello,Serlvet"); //这是在客户端（浏览器）上打印
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        this.doGet(req, resp);
    }
}

4.模块详解

(1)Mapping映射路径

  • (1)一个Servlet可以指定一个映射路径，可以指定多个映射路径，可以指定通用映射路径，可以默认请求路径等等。（以下web-demo为项目名）
    • 精准匹配：配置路径和访问路径一致。例如配置路径/user/select，此时访问路径为localhost:8080/web-demo/user/select。
    • 目录匹配：带有通配符，通配符的部分可以任意输入。例如配置路径/user/*，此时访问路径可以为localhost:8080/web-demo/aaa或是localhost:8080/web-demo/bbb等等。
    • 扩展名匹配：*.拓展名，符合拓展名的能访问。例如配置路径*.do，此时访问路径可以为localhost:8080/web-demo/aaa.do或是localhost:8080/web-demo/bbb.do等等。
    • 任意匹配：/或/*，写的页面都能访问。例如配置路径/*，此时访问路径可以为localhost:8080/web-demo/aaa或是localhost:8080/web-demo/bbb等等。注意：当配置了/，会覆盖掉tomcat中的DefaultServlet，则无法处理静态资源页面。

(2)HttpServletRequest

  • (1)Request继承体系：ServletRequest类，Java提供的请求对象根接口；HttpServletRequest类，Java提供的对Http协议封装的请求对象接口；RequestFacade，Tomcat定义的实现类。本质是Tomcat需要解析请求数据，封装为request对象并且创建request对象传递到service方法中。
    • 接口定义的方法实现类都需要实现，因此我们使用request对象时，只需要查阅JavaEE API文档的HttpServletRequest接口而不用去Tomcat里查找。
  • (2)HttpServletRequest代表客户端的请求，用户通过Http协议访问服务器，HTTP请求中的所有信息会被封装到HttpServletRequest，通过这个HttpServletRequest的方法，获得客户端的所有信息。HttpServletRequest和HttpServletResponse的方法一一对应。
  • (3)Request获取请求数据相关方法：
    • 请求行：请求方式/请求的资源路径及参数 请求的协议及版本号。如GET /request-demo/req1?username=zhangsan HTTP/1.1。
      • String getMethod()获取请求方式。如获取到上方的GET部分。
      • String getContextPath()动态获取虚拟目录（项目访问路径）。如获取到上方的/request-demo部分。
      • StringBuffer getRequestURL()获取URL（统一资源定位符）。如获取到上方http://localhost:8080/request-demo/req1部分。
      • String getRequestURI()获取URI（统一资源标识符）。如获取到上方的/request-demo/req1部分。
      • String getQueryString()获取请求参数（GET方式）。如获取到上方的username=zhangsan&password=123部分。
    • 请求头：键值对格式。客户端（浏览器）版本等信息。如User-Agent: Mozilla/5.0 Chrome/91.0.4472.106
      • String getHeader(String name)根据请求头名称，获取值。
    • 请求体：流的方式获取请求参数（Post方式）。这里的流无需关闭，随着请求结束，request对象销毁，服务器会关闭流。
      • ServletInputStream getlnputStream()获取字节输入流。
      • BufferedReader getReader()获取字符输入流。
  • (4)统一获取请求参数：GET请求方式和POST请求方式区别主要在于获取请求参数的方式不一样，有了统一获取请求参数的办法后就能统—doGet()和doPost()方法内的代码，只需要写其中一个（通常写在doGet()里），剩下一个（通常是doPost()）只需要写上this.doGet(req, resp);。此外，获取到的这些参数，底层放到一个Map集合中，因此我们获取参数即获取Map集合中的数据。
    • Map<String, String[]> getParameterMap()方法，获取所有参数Map集合。
    • String[] getParameterValues(Stringname)方法，根据名称获取参数值（数组）。
    • String getParameter(String name)方法，根据名称获取参数值（单个值）。
  • (5)Tomcat8.0以前版本，请求参数的中文乱码处理：
    • Post方式，增添下列代码：req.setCharacterEncoding("UTF-8");。
    • Get方式，原因是tomcat进行URL解码时默认了字符集ISO-8859-1而且我们无法对tomcat调整设置，解决方法为先使用getBytes ()方法将客户端（浏览器）给到我们的数据转换为字节数组（编码），再使用字符串构造方法把字节数组进行解码。即增添下列代码：new String(username.getBytes("ISO-8859-1"), "UTF-8");

package com.github.servlet;

import javax.servlet.ServletException;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.util.Arrays;

public class HttpServletRequestTest extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        req.setCharacterEncoding("UTF-8");
        resp.setCharacterEncoding("UTF-8");

        String username = req.getParameter("username");
        String password = req.getParameter("password");
        String[] hobbys = req.getParameterValues("hobbies");
        System.out.println("=============================");
        // 后台接收中文乱码问题
        System.out.println(username);
        System.out.println(password);
        System.out.println(Arrays.toString(hobbys));
        System.out.println("=============================");

        System.out.println(req.getContextPath());
        // 通过请求转发
        // 这里的 / 代表当前的web应用
        req.getRequestDispatcher("/success.jsp").forward(req,resp);
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        super.doPost(req, resp);
    }
}

(3)HttpServletResponse

  • (1)客户端和服务器之间的交互：web服务器接收到客户端的http请求，针对这个请求，分别创建一个代表请求的HttpServletRequest对象和代表响应的一个HttpServletResponse。
    • 如果要获取客户端请求过来的数据：找HttpServletRequest；如果要给客户端响应一些信息：找HttpServletResponse。
  • (2)Response继承体系：ServletResponse类，Java提供的请求对象根接口；HttpServletResponse类，Java提供的对Http协议封装的请求对象接口；ResponseFacade，Tomcat定义的实现类。本质是Tomcat需要解析请求数据，封装为response对象并且创建response对象传递到service方法中。
    • 接口定义的方法实现类都需要实现，因此我们使用response对象时，只需要查阅JavaEE API文档的HttpServletResponse接口而不用去Tomcat里查找。
  • (3)Response设置相应数据相关方法：
    • 1)响应行：协议版本号 响应状态码及描述。如HTTP/1.1 200 OK。
      • void setStatus(int sc)方法，设置响应状态码。参数sc对应上面响应行中的200。
    • 2)响应头：键值对格式。如Content-Type:text/html。
      • void setHeader(String name, Stringvalue)方法，设置响应头的键值对。
    • 3)响应体：流的方式设置数据。如<html><head></head><body></body></html>。这里的流无需关闭，随着响应结束，response对象销毁，服务器会关闭流。
      • PrintWriter getWriter()方法，获取字符输出流。
      • ServletOutputStream getOutputStream()方法，获取字节输出流。
  • (4)下载文件功能：
    • 思路：1)获取下载文件的路径；2)确认下载的文件名；3)让浏览器支持下载我们需要的东西；4)获取下载文件的输入流；（以下为IO流固定流程）5)创建缓冲区；6)获取OutputStream对象；7)将FileOutputStream流写入到buffer缓冲区；8)使用OutputStream将缓冲区中的数据输出到客户端。

package com.github.servlet;

import javax.servlet.ServletException;
import javax.servlet.ServletOutputStream;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.FileInputStream;
import java.io.IOException;
import java.net.URLEncoder;

public class FileServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
//        1. 获取下载文件的路径，此处写明了绝对路径
        String realPath = "F:\\java\\IDEA2020.2\\JavaWeb-02-Servlet\\response\\target\\classes\\01.png";
        System.out.println("下载文件的路径:" + realPath);
//        2. 确认下载的文件名
        String fileName = realPath.substring(realPath.lastIndexOf("\\") + 1);
//        3. Content-Disposition让浏览器支持下载我们需要的东西，这里还使用了URLEncoder.encode(fileName,"UTF-8")支持中文文件名
        resp.setHeader("Content-Disposition","attachment;filename="+ URLEncoder.encode(fileName,"UTF-8"));
//        4. 获取下载文件的输入流
        FileInputStream in = new FileInputStream(realPath);
//        5. 创建缓冲区
        int len = 0;
        byte[] buffer = new byte[1024];
//        6. 获取OutputStream对象
        ServletOutputStream out = resp.getOutputStream();
//        7. 将FileOutputStream流写入到buffer缓冲区
        while ((len=in.read(buffer)) > 0){
            out.write(buffer,0,len);
        }

        in.close();
        out.close();
//        8. 使用OutputStream将缓冲区中的数据输出到客户端
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        super.doPost(req, resp);
    }
}

import java.awt.*;
import java.awt.image.BufferedImage;
import java.io.IOException;
import java.util.Random;

public class ImageServlet extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws IOException {
//        如何让浏览器3秒自动刷新一次;
        resp.setHeader("refresh","3");

//        在内存中创建一个图片
        BufferedImage image = new BufferedImage(90,40,BufferedImage.TYPE_INT_RGB);
//        得到图片，创建画笔
        Graphics2D g = (Graphics2D) image.getGraphics();
//        设置图片的背景颜色
        g.setColor(Color.white);
        g.fillRect(0,0,90,40);
//        给图片写基础数据，背景色，字体等
        g.setColor(Color.RED);
        g.setFont(new Font(null,Font.BOLD,20));
        g.drawString(makeNum(),8,30);

//        告诉浏览器，这个请求用图片的方式打开
        resp.setContentType("image/jpeg");
//        网站存在缓存，不让浏览器缓存
        resp.setDateHeader("expires",-1);
        resp.setHeader("Cache-Control","no-cache");
        resp.setHeader("Pragma","no-cache");

//        把图片写给浏览器
        ImageIO.write(image,"jpg", resp.getOutputStream());

    }

//    生成随机数
    private String makeNum(){
        Random random = new Random();
        String num = random.nextInt(9999999) + "";
        StringBuffer sb = new StringBuffer();
        for (int i = 0; i < 7-num.length() ; i++) {
            sb.append("0");
        }
        num = sb.toString() + num;
        return num;
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        super.doPost(req, resp);
    }

5.数据共享

(1)会话跟踪

1）概念

  • 1)用户打开一个浏览器，点击了多个超链接，访问多个web资源，关闭浏览器，这个过程可以称之为（一次）会话。一次会话可以包括多次请求和响应。会话跟踪：服务器需要识别多次请求是否来自于同一浏览器，以便在同一次会话的多次请求间共享数据。在实际开发中我们必须考虑到同一用户在不同页面（不同的servlet）之间共享数据，由此出现了会话跟踪技术。request解决了一次请求内的数据共享问题，session解决了用户不同请求的数据共享问题，ServletContext解决了不同的用户的数据共享问题。
  • 2)类型：
    • 传统技术Cookie和Session：
      • 客户端会话跟踪技术Cookie：把用户的数据写给用户的浏览器，浏览器保存，且可以保存多个。常用在用户未登录前的各种情况，应用场景：购物车、保存密码记住我功能（但无法保证安全性）。
      • 服务端会话跟踪技术Session：当用户打开浏览器访问某个网站时，服务器就会在服务器的内存为该浏览器分配一个空间，该空间被这个浏览器独占。Session对象由服务器创建，服务器端保存，一般保存重要的信息，减少服务器资源的浪费。常用在用户未登录后需要确保安全性的各种情况，应用场景：用户登录、验证码。
    • 令牌技术。

2）cookie

  • 1)优缺点：
    • 优点：HTTP协议中支持的技术。
    • 缺点：
      • 移动端APP无法使用Cookie。
      • 不安全，用户可以自己禁用Cookie。
      • Cookie不能跨域。
  • 2)过程：第一次登陆时，服务器响应给客户端Cookie，下次请求时客户端携带这个Cookie给服务器核对。
    • (A)发送cookie：
      • Cookie cookie = new Cookie("key","value");方法，创建Cookie对象，设置数据。
      • response.addCookie(cookie);方法，使用response对象发送Cookie到客户端。
    • (B)获取cookie：
      • Cookie[] cookies = request.getCookies();方法，使用request对象获取客户端携带的所有Cookie
      • 遍历数组，获取每一个Cookie对象。
      • cookie.getName();和cookie.getValue();方法，使用Cookie对象方法获取键和值数据。
  • 3)细节：
    • (A)默认情况下，Cookie存储在浏览器内存中，当浏览器关闭，内存释放，则Cookie被销毁。cookie的有效期，可以通过setMaxAge(int seconds)方法设置Cookie存活时间：
      • 其参数seconds秒数若为正数，表示将Cookie写入浏览器所在电脑的硬盘，持久化存储，到时间自动删除。
      • 其参数seconds秒数若为负数（默认值），则Cookie在当前浏览器内存中，当浏览器关闭，则Cookie被销毁。
      • 其参数seconds秒数若为0，删除对应cookie。
    • (B)Cookie一般会保存在本地电脑的用户目录下appdata内。
    • (C)一个网站的cookie是存在上限的，Cookie大小有限制约4kb，一个Cookie只能保存一个信息，一个web站点可以给浏览器发送多个Cookie，最多存放20个Cookie。
    • (D)Cookie不能直接存储中文如需要存储，则需要通过URL编码进行转码，使用URLEncoder.encode()方法和URLDecoder.decode()方法。

package com.github.servlet;

import javax.servlet.ServletException;
import javax.servlet.http.Cookie;
import javax.servlet.http.HttpServlet;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.io.PrintWriter;
import java.util.Date;

/**
 * 保存用户上一次访问的时间
 */
public class CookieDemo01 extends HttpServlet {
    @Override
    protected void doGet(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        // 服务器，告诉你，你来的时间，将这个时间封装为一个信件
        // 解决中文乱码问题
        req.setCharacterEncoding("UTF-8");
        resp.setCharacterEncoding("UTF-8");
        resp.setContentType("text/html; charset=UTF-8");

        PrintWriter writer = resp.getWriter();

        // Cookie,服务端从客户端获取
        Cookie[] cookies = req.getCookies();
        // 这里返回数组，说明Cookie可能存在多个

        // 判断Cookie是否存在
        if(cookies!=null){
            // 如果存在，遍历数组
            writer.write("您上一次访问的时间是:");
            for (int i = 0; i < cookies.length; i++) {
                Cookie cookie = cookies[i];
                // 获取Cookie的名字
                if(cookie.getName().equals("lastLoginTime")) {
                    // 获得cookie中的value
                    long parseLong = Long.parseLong(cookie.getValue());
                    Date date = new Date(parseLong);
                    writer.write(date.toLocaleString());
                }
            }
        }else{
            writer.write("第一次访问本站");
        }

        // 服务端给客户端响应一个Cookie;
        Cookie cookie = new Cookie("lastLoginTime", System.currentTimeMillis()+"");

        resp.addCookie(cookie);
    }

    @Override
    protected void doPost(HttpServletRequest req, HttpServletResponse resp) throws ServletException, IOException {
        super.doPost(req, resp);
    }
}

3）session

  • 1)优缺点：
    • 优点：存储在服务端，安全。
    • 缺点：
      • 服务器集群（多台服务器）环境下无法直接使用Session。
      • 和Cookie相同的缺点，移动端APP无法使用；不安全，用户可以自己禁用；不能跨域。
  • 2)Session底层是基于Cookie实现的，Session储存在服务端。Session是服务器技术，服务器会给每一个用户（浏览器）创建一个Seesion对象（登记SeesionId并把这个SeesionId告诉用户），一个Seesion独占一个浏览器，只要浏览器没有关闭，这个Session就存在，也就是说用户登录之后，整个网站都可以实现访问。技术上来说为使用HttpSession接口，来实现一次会话的多次请求间数据共享功能：
    • (A)获取Session对象：
      • HttpSession session = request.getSession();方法，创建Session对象。
    • (B)存取数据：
      • void setAttribute(String name, Object o)方法，存储数据到session域中。
      • Object getAttribute(String name)方法，根据key，获取值。
      • void removeAttribute(String name)方法，根据key，删除该键值对。
  • 3)Session的钝化与活化，实现服务器正常重启后，Session也不会丢失。
    • 钝化：在服务器正常关闭后，Tomcat会自动将Session数据写入硬盘的文件中。
    • 活化：再次启动服务器后，从文件中加载数据到Session中。
  • 4)Session的销毁：
    • 默认情况下，无操作，30分钟自动销毁。销毁时间可以在web.xml中通过<session-timeout></session-timeout>标签进行设置，而默认30分钟销毁实际上是在Tomcat的配置文件中的原始数据。
    • 调用Session对象的invalidate()方法进行销毁。

  • 3)转发和重定向的区别：
    • 二者都会实现页面跳转。请求转发的时候，url不会产生变化；重定向时候，url地址栏会发生变化。
    • 请求转发只能转发到当前服务器的内部资源；重定向可以重定向到任意位置的资源，无论是服务器内部、外部均可。
    • 请求转发只有1次请求，可以在多个资源使用request共享数据；重定向包括了2次请求，不能在多个资源使用request共享数据。
    • 请求转发本质是由服务器使用内部资源，因此不需要加上项目访问路径；重定向本质是由客户端（浏览器）使用内部资源，因此需要加上项目访问路径（不然无法确定位置）。
