1.底层知识

  • (1)Spring容器默认创建的对象是单例，即一个对象。如果我们需要多个对象，修改Spring配置文件。

2.基础配置

  • (1)格式：
1
2
3
4
5
6

<beans>
    <!--不存在依赖关系的bean用这个标签-->
    <bean/>
    <!--存在依赖关系的bean用这对标签-->
    <bean></bean>
</beans>
  • (2)属性说明：
    • id：使用容器可以通过id值获取对应的bean，在一个容器中id值唯一。
    • class：对应具体的类，使用全路径类名。
    • name：起别名，getBean()传参的时候传入别名也可以识别。允许起多个别名，用空格/逗号/分号分隔，例如<bean id="bookDao" name = "abc deg bookEri" class="src.main.com.retreatafter.dao.impl.BookDaoImpl"/>。
    • property：setter注入时，配置当前bean的属性。
      • name：指向关联的类下对象名。
      • ref：引用，指向关联的类的bean的id名。
      • value：赋值。
    • constructor-arg：构造器注入时，配置当前bean的属性。
      • name：指向构造器中的形参。
      • ref：引用，指向关联的类的bean的id名。
      • type：参数类型。（了解）
      • index：参数的序号，从0开始。（了解）
    • autowire：自动装配。常用byType按类型注入。
    • scope：作用范围，在这里表示创建对象的模式，值默认为singleton，修改为prototype可以创建多个对象。例如<bean id="bookDao" name = "abc deg bookEri" class="src.main.com.retreatafter.dao.impl.BookDaoImpl" scope="prototype" />。
    • factory-method：工厂模式项目的代码中，静态/实例工厂生成对象的方法名。
    • factory-bean：工厂模式项目的代码中，实例工厂生成对象的类名。
    • init-method：生命周期控制，调用对应的初始化后操作。
    • destory-method：生命周期控制，调用对应的销毁前操作。
    • 集合标签：array表示数组，list表示list集合、set表示set集合、map表示map集合（并配合entry标签使用）。
    • props：表示properties。

3.Bean的实例化

(1)一般情况

  • 1)bean本质上就是对象，创建bean也是通过（无参的）构造方法完成。

(2)静态工厂

  • 1)Bean的实例化过程：
    • 以工厂设计模式中静态工厂来生成对象的项目，容器要接管生成对象，需要在bean中class属性写工厂的类名，并使用factory-method属性写明静态工厂生成对象的方法名。示例：
1
2
3
4
5
6

//静态工厂，工厂模式的目的就是用于生成多个对象
public class OrderDaoFactory {
    public static OrderDao getOrderDao(){
        return new OrderDaoImpl();
    }
}

1
2

//对应的Spring配置文件
<bean id="orderDao" factory-method="getOrderDao" class="com.retreatafter.factory.OrderDaoFactory"/>

(3)实例工厂

  • 1)Bean的实例化过程：
    • 实例工厂没有static静态关键字，因此工厂设计模式的工厂要创建对象才能调用方法，需要先配置工厂的bean，其中factory-method属性为生成对象的方法，factory-bean属性表示谁是原本哪个生成对象的。示例：
1
2
3
4
5
6

//实例工厂，工厂模式的目的就是用于生成多个对象
public class UserDaoFactory {
    public UserDao getUserDao(){
        return new UserDaoImpl(); //生成对象
    }
}

1

3
4

//对应的Spring配置文件
<!--factory-bean是对应id-->
<bean id="userDaoFactory" class="com.retreatafter.factory.UserDaoFactory"/>
<bean id="userDao" factory-method="getUserDao" factory-bean="com.retreatafter.factory.userDaoFactory"/>
  • 2)在以上方法中，可以看到Spring配置文件里UserDaoFactory对应的bean实际上是配合userFactory对应的bean使用的，UserDaoFactory对应的bean实际上没有别的意义，改良后，实现FactoryBean<>接口，并修改对应的Spring配置文件。

public class UserDaoFactoryBean implements FactoryBean<UserDao>{ //泛型<>中写要造的对象类型，我们要UserDao类型的对象
    //创建实例，统一创建对象的方法名，替代掉上述的UserDaoFactory类中的public UserDao getUserDao()方法
    public UserDao getObject() throws Expection{
        return new UserDaoImpl(); //生成对象
    }
    //创建什么类型
    public Class<?> getObjectType(){
        return UserDao.class; //反射的内容，UserDao.class获取UserDao的字节码
    }
    //可以直接在这个类设置创建对象的模式
    public boolean isSingleton() {
				return false; //默认true，false相当于之前配置文件中scope设为prototype，可以创建多个对象
		}
}

4.生命周期

(1)前置操作

  • 1)生命周期是指从创建到消亡的完整过程，我们要对Bean的生命周期进行控制，是在创建后到销毁前这段期间实现。过程为：
    • (A)初始化容器
      • 创建对象（内存分配）
      • 执行构造方法
      • 执行属性注入（set操作）
      • 执行bean初始化方法
    • (B)使用bean
      • 执行业务操作
    • (C)关闭/销毁容器
      • 在销毁容器前，执行bean销毁方法
  • 2)以下列类为例：

    public static void main(String[] args) {
        /**这里无法调用销毁方式是因为程序执行完毕后JVM直接退出，未执行关闭ClassPathXmlApplicationContext对象
        *要想在这里看到destory()销毁方法实现，可以在测试类改为ClassPathXmlApplicationContext context = new ClassPathXmlApplicationContext("applicationContext.xml");

//Service层实现
public class BookServiceImpl implements BookService {
    private BookDao bookDao; //仅定义，而不new对象
    
    public void save() {
        System.out.println("bookservice save...");
        bookDao.save();
    }
    
    //提供set方法
    public void setBookDao(BookDao bookDao) {  
		    System.out.println("set...");
		    this.bookDao = bookDao;  
    }

    @Override
    public void destroy() throws Exception {
        System.out.println("service destory");
    }

    @Override
    public void afterPropertiesSet() throws Exception {
        System.out.println("service init");
    }
}
