1.事务Transaction

(1)概念

  • 1)事务是一组操作的集合，它是一个不可分割的工作单位。事务会把所有的操作作为一个整体一起向系统提交或撤销操作请求，即这些操作要么同时成功，要么同时失败。就像A向B转账，只可能出现转账成功两人的账户金额都变动，或者转账失败两人的账户金额都不变动。
  • 2)事务的ACID原则：A(Atomic)原子性、C(Consist)一致性、I(Isolated)隔离性、D(Durable)持久性。
    • A(Atomicity)原子性：事务是不可分割的最小单元，事务中的所有操作，要么全部完成，要么全部不完成。
    • C(Consistency)一致性：事务前后数据的完整性必须保持（最终）一致。
    • I(Isolation)隔离性：多个开发事务间要相互隔离。
    • D(Durability)持久性：事务如果没有提交，恢复到原状；一个事务一旦被提交，对数据库中数据的改变就是永久性的。
  • 3)事务的隔离级别
    • 脏读：指一个事务读取了另外一个事务未提交的数据。
    • 不可重复读：在一个事务内读取表中的某一行数据，多次读取结果不同，例如生成报表时结果金额数据又发生了变动。（这个不一定是错误，只是某些场合不对）。
    • 虚读（幻读）：在一个事务内读取到了别的事务插入的数据，导致前后读取数量总量不一致。

(2)执行

  • 1)在MySQL中事务是默认自动提交的，也就是说，当执行一条DML语句，MySQL会立即隐式的提交事务。因此手动使用事务时应先关闭自动提交。
  • 2)手动开启事务流程：关闭自动提交→手动开启事务→（成功提交则持久化，提交失败则回滚到原数据即关闭自动提交那步）→成功提交，事务结束，开启自动提交。
    • 开启事务：start transaction; / begin;
    • 提交事务：commit;
    • 回滚事务：rollback;

-- 语法

-- MySQL开关自动提交事务
SET autocommit = 0;   -- 关闭
SET autocommit = 1;   -- 开启(默认情况)

-- 手动处理事务

-- 事务开启
START TRANSACTION;  -- 开始一个事务，标记事务的起始点，在这之后的SQL都会算在同一个事务内

INSERT XX
INSERT XX

-- 中间可能会存在的保存点
SAVEPOINT 保存点名称; -- 设置一个事务保存点
ROLLBACK TO SAVEPOINT 保存点名称; -- 回滚到保存点
RELEASE SAVEPOINT 保存点名称; -- 删除保存点

-- 成功，则提交：持久化
COMMIT;

-- 失败，则回滚：数据回到本次事务的初始状态
ROLLBACK;

-- 事务结束将自动提交事务重新开启
SET autocommit =1;  -- 开始自动提交

/*题目：
	A有2000元余额，现需要买一款价格为500元商品，对商户B进行网上银行转账
	此时，商户B的余额为10000元*/

-- 创建数据库
CREATE DATABASE `shop` CHARACTER SET utf8 COLLATE utf8_general_ci;
USE `shop`;

-- 建表并设定基础列
CREATE TABLE `account` (
`id` INT(11) NOT NULL AUTO_INCREMENT,
`name` VARCHAR(32) NOT NULL,
`money` DECIMAL(9,2) NOT NULL,
PRIMARY KEY (`id`)
) ENGINE=INNODB DEFAULT CHARSET=utf8;

-- 插入数据
INSERT INTO account (`name`,`money`)
VALUES('A',2000.00),('B',10000.00);

-- 模拟转账，使用事务
SET autocommit = 0; -- 关闭自动提交
START TRANSACTION;  -- 开始一个事务
UPDATE account SET money=money-500 WHERE `name`='A';
UPDATE account SET money=money+500 WHERE `name`='B';
COMMIT; -- 提交事务，持久化
# ROLLBACK; -- 失败则回滚
SET autocommit = 1; -- 恢复自动提交

2.索引Index

(1)概念

  • 1)索引是数据结构，用于帮助MySQL高效获取数据。MySQL数据库支持的索引结构有很多，如：Hash索引、B+Tree索引、Full-Text索引等。我们平常所说的索引，如果没有特别指明，都是指默认的 B+Tree 结构组织的索引。
  • 2)特点：
    • 优点：索引在小数据量的时候用处不大，但是在大数据的时候区别（速度提升）十分明显。索引提高了数据查询的效率，降低数据库的IO成本、通过索引列对数据进行排序，能够降低数据排序的成本，降低CPU消耗。
    • 缺点：索引会占用存储空间；索引大大提高了查询效率，但因为多了一个索引结构需要维护，就会降低insert、update、delete的效率。

(2)类型

  • 1)主键索引Primary Key，唯一的标识，主键不可重复，只能有一个列作为主键。在建表时，会自动创建主键索引。
  • 2)唯一索引Unique Key，避免重复的列出现，唯一索引可以重复可以有多个，多个列都可以标识唯一索引。添加唯一约束时，数据库实际上会添加唯一索引。
  • 3)常规索引Index/Key，默认的，用Index关键字或Key关键字来设置。
  • 4)全文索引FullText Key，快速定位数据。只有字段的数据类型为 char、varchar、text 及其系列才可以建全文索引。

(3)语法

  • 1)创建索引：create [unique] index 索引名 on 表名 (字段名,... );。
  • 2)查看索引：show index from 表名;。
  • 3)删除索引：drop index 索引名 on 表名;。

-- 示例代码

-- 显示所有的索引信息
SHOW INDEX FROM `student`;

-- 增加全文索引
ALTER TABLE `school`.`student` ADD FULLTEXT INDEX `studentname` (`studentname`);

-- EXPLAIN : 分析SQL语句执行性能
EXPLAIN SELECT * FROM `student`;  -- 非全文索引

-- 做数据匹配
EXPLAIN SELECT * FROM `student` WHERE MATCH(`studentname`) AGAINST('赵');

(4)原则

  • 1)索引不是越多越好。
  • 2)小数据量的表建议不要加索引。
  • 3)不要对经常变动的数据加索引。
  • 4)索引一般应加在经常进行查找的字段。

3.权限管理

(1)用户管理

  • MySQL中的用户管理是可视化进行的。
  • 用户表的相关操作，用户表也是表，本质依旧是增删改查，首先，MySQL有专门的用户表，名为mysql.user。我们需要对（使用数据库的）用户进行的操作通常为创建、授权、设置密码、删除。

(2)创建用户和修改密码

  • 1)创建用户
    • 语法：CREATE USER 用户名 IDENTIFIED BY [PASSWORD] '密码(字符串)'

2
3

-- 示例代码
-- 创建一个用户名为retreatafter密码为123456的用户
CREATE USER retreatafter IDENTIFIED BY '123456';
  • 2)修改密码
    • 修改当前用户密码，语法：SET PASSWORD = PASSWORD('新密码');
    • 修改指定用户密码，语法：SET PASSWORD FOR 用户名 = PASSWORD('密码');
  • 3)用户重命名
    • 语法：RENAME USER 旧用户名 TO 新用户名;
  • 4)授予权限
    • 语法：GRANT 权限列表 ON [库名.]表名 TO 用户名 [IDENTIFIED BY [PASSWORD] 'password']

  • 7)删除用户
    • 语法：DROP USER 用户名;
