1.概述

  • (1)AOP(Aspect Oriented Programming)面向切面编程与OOP(Object Oriented Programming)面向对象编程一样，都是一种编程的思想。AOP思想即在不惊动原始设计（无侵入式）的基础上进行功能增强，追加功能。
    • 分析项目功能，找出切面(Aspect)。
    • 安排切面的执行时间，使用通知(Advice)表示。
    • 安排切面的执行位置，使用切入点(Pointcut)表示。
  • (2)核心概念
    • 1)连接点(JoinPoint)：程序执行过程中的任意位置，可以为执行方法，抛出异常，设置变量等。可以看作原始方法。
    • 2)切入点(Pointcut)：是多个连接点方法的集合。在SpringAop中，一个切入点可以只描述一个具体方法，也可以匹配多个方法。
      • 定义切入点使用注解@Pointcut。
      • 切入点定义依托一个不具有实际意义的方法进行，即无参数，无返回值，方法体无实际逻辑。
    • 3)通知类：抽出程序要重复用到的共性功能，定义为通知类。
    • 4)通知(Advice)：表示切面功能何时执行。
    • 5)切面(Aspect)：描述通知与切入点的对应关系，表示增强的功能，通常是非业务功能。
  • (3)整个AOP的实现过程是用设计模式中的代理模式进行的，AOP下其实是用代理对象去实现。AOP是动态代理的规范化。
    • 目标对象(Target)：原始功能去掉共性功能对应的类产生的对象，这种对象是无法直接完成最终工作的。被代理的原始对象成为目标对象。
    • 代理(Proxy)：目标对象无法直接工作，需要对其进行功能回填，通过原始对象的代理对象实现。

4.切入点表达式

(1)概念

  • 1)切入点：要进行增强的方法。
  • 2)切入点表达式：要进行增强方法的描述方式。在上述案例中，我们写的@Pointcut("execution(void src.main.com.retreatafter.dao.BookDao.update())")中execution(void src.main.com.retreatafter.dao.BookDao.update())这部分就叫切入点表达式。

(2)格式

  • 1)标准格式：动作关键字(访问修饰符，返回值，包名，作为切入点的类/接口.作为切入点的方法名(参数) 异常名)。其中访问修饰符和异常名可以省略。可以使用通配符简化描述：
    • *:单个独立的任意符号，可以独立出现，也可以作为前缀或者后缀的匹配符出现。至少有1个。例如execution(public * com.retreatafter.*.UserService.find*(*))表示返回值任意，并匹配com.retreatafter包下的任意包中的UserService类或接口中所有find开头的（例如findaaa()）带有一个参数的方法。
    • ..：多个连续的任意符号，可以独立出现，表示当前包及子包，常用于简化包名与参数的书写。可以为0个。例如execution(public User com..UserService.findById(..))表示匹配com包下的任意包中的UserService类或接口中所有名称为findById的方法。
    • +：专用于匹配子类类型。例如execution(* *..*Service+.*(..))，其中*Service+，表示所有以Service结尾的接口的子类，很少用到。
  • 2)原则：
    • 描述切入点通常描述接口，而不描述实现类，这是降低紧耦合的问题。
    • 返回值类型对于增删改类使用精准类型加速匹配，对于查询类使用*通配快速描述。
    • 包名书写尽量不使用..匹配，常用*做单个包描述匹配，或精准匹配。
    • 接口名/类名书写名称时，与模块相关的采用*匹配，例如UserService书写成*Service，绑定所有业务层接口名。

5.AOP通知类型

(1)概念

  • AOP通知描述了抽取的共性功能，既然我们抽取出去了一部分功能，就需要考虑到这个功能什么时候执行。
    • 1)【重要】环绕通知：使用注解@Around()的通知方法，它可以追加功能到方法执行的前后。最常用。
    • 2)【重要】前置通知：使用注解@Before()的通知方法，追加功能到方法执行前运行。
    • 3)后置通知：使用注解@After()的通知方法，追加功能到方法执行后运行。
    • 4)【重要】返回后通知：使用注解@AfterReturning()的通知方法，原始方法运行完毕之后再执行追加功能，如果原始方法出现异常，那么该通知方法不会运行。
    • 5)抛出异常后通知：使用注解@AfterThrowing()的通知方法，追加功能到方法抛出异常后，只有方法执行出异常才进行。

(2)环绕通知

  • 1)作用：
    • 环绕通知是功能最强的通知类型。
    • 它在目标方法的前和后都能增强功能、能够控制目标方法是否被调用执行、能够修改原来的目标方法的执行结果，影响最后的调用结果。
  • 2)注意事项：
    • (A)环绕通知必须依赖形参ProceedingJoinPoint才能实现对原始方法的调用，进而实现原始方法调用前后同时添加通知。
    • (B)通知中如果未使用ProceedingJoinPoint对原始方法进行调用将跳过原始方法的执行，根据这点可以实现权限管理。
    • (C)对原始方法的调用可以不接收返回值（不建议），通知方法设置成void即可，如果接收返回值，最好设定为Object类型。原始方法的返回值如果是void类型，通知方法的返回值类型可以设置成void，也可以设置成Object。
    • (D)由于无法预知原始方法运行后是否会抛出异常，因此环绕通知方法必须要处理Throwable异常。

//已经抽取出来的通知类中的一个方法
@Around("pt()")
public Object around(ProceedingJoinPoint pjp) throws Throwable{ //要确定原本的代码中谁先执行谁后执行，通过ProceedingJoinPoint pjp这个参数调用方法完成，属于固定写法.且标准写法为返回Object类型返回值
    System.out.println("around before advice ..."); //这个方法第1个执行
    //原始方法的调用
    Object ret = pjp.proceed(); //原始方法第2个执行。这里是否返回参数根据原始方法情况而定
    System.out.println("arround after advice ..."); //这个方法第3个执行
    return ret;
}
