1.概述

  • (1)Spring Boot可以创建两种类型的Web应用：
    • 基于Servlet体系的SpringWebMVC应用。
    • 使用 spring-boot-starter-webflux模块来构建响应式，非阻塞的Web应用程序。

2.构建第一个Web应用

(1)步骤分析

  • 1)搭建环境。
    • 创建SpringBoot的maven项目，并勾选导入依赖：spring-web依赖（其中包含了SpringMVC，Restful，Tomcat）、Thymeleaf依赖（视图技术，替代jsp）、Lombok依赖（可选）。
  • 2)测试代码业务实现。
    • 创建控制器类Controller。控制器类Controller使用到@Controller注解声明为Bean由Spring创建管理对象和@RequestMapping注解绑定请求地址和方法。
    • 创建发起请求的页面jsp和作为显示请求处理结果的jsp。

(2)搭建环境

  • 1)创建SpringBoot的maven项目，并勾选导入依赖：spring-web依赖（其中包含了SpringMVC，Restful，Tomcat）、Thymeleaf依赖（视图技术，替代jsp）、Lombok依赖（可选）。

@Controller
public class MyController {
    //请求映射注解@RequestMapping，绑定请求地址和方法，表示该地址传来的请求由该方法处理
    @RequestMapping("/exam/quick")

        model.addAttribute("time",LocalDateTime.now());

        return "quick";
    }
}

3.JSON视图

  • (1)上述例子以Html文件作为视图，可以编写复杂的交互的页面，CSS美化数据。除了这种带有页面的数据，还有一种只需要数据的视图，例如手机应用app，app的数据来自服务器应用处理结果，只需要数据。主流方式是服务器返回json格式数据给手机app应用。

4.视图技术Thymeleaf

(1)概念

  • 1)Thymeleaf是一个表现层的模板引擎，一般被使用在Web环境中，它可以处HTML、XML、JS等文档，即可以将JSP作为JavaWeb应用的表现层，是JSP的代替技术。

(2)表达式

  • 1)变量表达式，格式：${...}，可用于获取后台传来的数据。，例如<p th:text="userName">zhangsan</p>。
  • 2)链接表达式，格式：@{...}，实现超链接网址，例如th:href="@{/css/home.css}"。

5.MVC

(1)Controller

  • 1)常用注解：@RestController及@Controller。
    • @RestController包含了@ResponseBody注解和@Controller注解，使用@RestController注解后当前控制器中所有方法都会默认加入@ResponseBody注解的功能，即此时方法返回值为数据，可以通过HttpServletResponse对象输出给浏览器。
  • 2)Controller功能：接收请求，响应数据，具体来说，Controller类中的方法，方法上的注解@RequestMapping(value="请求的url地址" method=请求方式)/@GetMapping/@PostMapping/@PutMapping/@DeleteMapping代表了来自该地址的请求由该方法进行处理，并且注解可以进一步描述是什么类型的请求如区分get/post/put/delete请求；方法的形参接收请求中的参数；方法的返回值表示应答结果，结果可以包括数据和视图。
    • url地址除了唯一匹配外，允许使用以下格式：
      • 使用?表示单个字符，例如@GetMapping("file/t?st.html")；
      • 使用*表示0个或多个字符，例如@GetMapping("/images/*.gif")；
      • 使用**表示所有，多个路径或是多个字符，例如@GetMapping("/pic/**")；
      • 使用路径变量{*变量名称}，例如@GetMapping("/order/{*id}")；
      • 使用正则表达式。
  • 3)请求参数验证：
    • 除了基础的手工验证外，还可以使用JavaBeanValidation：JSR-303是JAVAEE6中的一项子规范，是在运行时进行数据验证的规范，为JavaBean验证定义了相应的元数据模型和API。hibernate-validator是它的实现。
    • 使用步骤：添加spring-boot-starter-validation依赖，选择需要的注解即可实现验证。

(2)Model

  • 1)后台要从控制层直接返回前端所需的数据，这时就会用到Model。ModelAndView里的任意值，以及json格式的字符串等都是Model。

(3)View

  • 1)返回值类型：
    • 页面视图：返回值为String直接return指定视图页面，或是返回值为ModelAndView，包含数据和视图。
    • JSON数据视图：返回值为自定义对象。
      • 复杂JSON，即一个类中存在多个引用类型或集合类型。
    • ResponseEntity应答实体：包含了数据和自定义的HttpStatus Code。
    • Map：默认将key和value转换为json字符串。

(1)servlet

//控制器类
@Restcontroller
public class UploadFilecontroller {
    //上传文件
    @PostMapping("/uploadFile")
    public String uploadFile(@RequestParam("upfile") MultipartFile multipartFile){
        System.out.println("开始处理上传文件");
        Map<String,Object> info = new HashMap<>();

        try{
            //判断上传了文件
            if( !multipartFile.isEmpty()){
                info.put("上传文件的参数名称", multipartFile.getName());
                info.put("内容类型", multipartFile.getContentType());
                var ext = "unknown";
                var filename = multipartFile.getOriginalFilename(); //原始文件名称
                if(filename.indexOf(".")>0){
                    ext = filename.substring(filename.indexOf(".")+1);
                }
                //生成服务器使用的文件名称
                var newFileName = UUID.randomUUID().toString()+ext;
                var path="D://upload"; //存储服务器的文件
                //把文件保存到path目录
                multipartFile.transferTo(new File(path));
                info.put("文件名称", newFileName);
            }
      }catch (Exception e){
          e.printStackTrace();
      }
      //重定向到index页面
      return "redirect:/index.html";
    }
}

8.异常处理

  • (1)在Controller处理请求过程中发生了异常时，DispatcherServlet会将异常处理委托给异常处理器（处理异常的类）。实现HandlerExceptionResolver接口的都是异常处理类。
  • (2)常用注解：@ExceptionHandler、@ControllerAdvice、@RestControllerAdvice

  • (1)远程访问是一个应用能够访问其他应用的功能。
  • (2)注解@HttpExchange。
  • (3)响应式异步WebClient。

10.AOT与JIT

  • (1)AOT：预编译，提前编译，静态的。提供应用启动时间，SpringBoot3增加了对AOT的支持。
  • (2)JIT：实时编译，动态的。提供应用程序执行的性能。
  • (3)Native Image原生镜像（本机镜像）：将java程序编译为可独立执行的文件的技术。
