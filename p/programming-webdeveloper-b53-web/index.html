1.静态网页与动态网页

  • (1)Web(World Wide Web)，即网页，又分为静态网页和动态网页。静态网页提供给用户看的数据始终不会发生变化，常见的语言有html，css，最大的缺陷是无法和数据库交互，这样数据无法持久化，用户无法交互；动态网页提供给用户看的数据是变化的，每个用户在不同时间不同地点看到的数据都有可能是不同的，常见的语言有Servlet/JSP，ASP，PHP，它弥补了静态网页的缺点，而动态网页的缺点是一旦动态web资源出现了错误，需要重新编写后台程序重新发布。
  • (2)在Java中，开发动态Web资源的技术统称为JavaWeb。（开发网站）其三大组件：Servlet、Filter、Listener。

2.Web程序开发

  • (1)可以提供浏览器访问的程序称为Web程序，其实现流程：
    • 1)前端发送请求：Web程序通过浏览器访问页面，前端页面使用异步提交的方式发送请求到后端服务器。
    • 2)后端服务器采用MVC三层架构表现层、业务层、数据层的三层架构的形式进行开发：
      • 表现层→业务层→数据层：页面发送的请求由表现层接收，获取用户的请求参数后将参数传递到业务层，业务层访问数据层。
      • 数据层→业务层→表现层：得到用户需要的数据后，返回数据给表现层，表现层将数据转换为json格式发送给前端页面。
    • 3)前端响应：前端页面接收数据后解析数据，并组织成用户浏览的最终页面信息交给浏览器。
  • (4)web应用程序编写完毕后，若想提供给外界访问，需要一个服务器来统一管理，也就是之后会需要学习的Tomcat服务器。

3.Web发展架构

  • (1)在未来，我们还会接触到许多概念，实际上它们都是从需求扩张发展一步步更新迭代的：
    • 单机架构：早期，一个网站只需要应用程序（服务器）和数据库，所用到的技术LAMP（Linux+Apache+Mysql+PHP）即可覆盖。并进行基本的应用与数据分离解决资源争抢问题，应用服务器负责处理请求、业务逻辑；数据库负责存数据、进行IO操作。
    • 高并发：
      • 应用集群：多台服务器处理相同业务。
      • 负载均衡：将请求均匀地分配到每台应用服务器。
      • 水平拓展：增加服务器数量。
      • 高可用：某一台服务器不可用时可以自动屏蔽流量（请求），其它服务器接手处理请求。
    • 分布式数据库：
      • 热点读：
        • 多级缓存：放置用户经常访问的热数据（数据库结果+页面+接口结果+计算结果+静态资源等等），减轻数据库压力，三层缓存包括浏览器缓存、应用服务器本地缓存、分布式缓存Redis。用户每次请求会先去缓存进行查找，三层缓存都没有才会去访问数据库。
      • 请求与非热点读：
        • 读写分离：主库Master负责写，从库Slave负责读，并通过数据同步以保证主从数据一致。
        • 拆库拆表：
          • 垂直分库：按业务拆分数据库表。
          • 水平分库：一张大表拆分为多张小表，配合数据库中间件，对应用透明。
    • 访问速度与系统安全优化
      • CDN：将静态资源分布在多个节点，用户发送请求时会将距离用户最近的节点的资源响应给用户。
      • 反向代理：在用户和应用服务器之间的中间层，公网请求会先访问中间层，再转发给内网应用服务器，隐藏真实服务器，减少服务器被攻击的可能，并且支持流量清洗、权限校验。
      • 搜索引擎：倒排索引使搜索秒级响应。
      • NoSQL数据库：存储非结构化半结构化数据，并支持高并发易扩展。
    • 分布式架构：
      • 分布式架构：对应用服务器进行拆分，每个系统单独部署、单独发布、单独扩容。
      • RPC远程调用：解决各个系统相互调用的问题，实现跨机器调用通讯。
      • 服务注册与发现中心：管理所有服务地址，请求地址会先进入到中心。
      • 请求队列：服务之间不用再相互等待，在需要对应消息时从请求队列中获取。
    • 微服务架构：
      • 微服务架构：每个小服务只做一件事，能够独立开发、独立发布、独立扩容。
      • 全链路追踪：定位速度慢的服务。
      • 限流、熔断、降级：当流量过大时对系统进行保护。
      • 服务治理：统一监控服务，日志权限。
      • Docker容器：统一微服务代码依赖、配置环境，一次打包，到处运行。
      • k8s：容器自愈、扩缩容。
    • 云原生
      • 云原生：将系统搬至云平台。

4.Web服务器

  • (1)B/S架构：浏览器和服务器。C/S架构：客户端和服务器。
  • (2)服务器工作的本质：接收请求，返回响应。即服务器是一种被动的操作，用来处理用户的一些请求和给用户一些响应信息。

6.Http协议

  • (1)定义：Http全称HyperText Transfer Protocol，超文本传输协议，规定了浏览器与服务器之间数据传输的规则。
    • 文本是例如字符串、html……之类的格式，超文本也即不仅限于文本，例如图片、视频、定位……

  • (2)请求协议：
    • 1)请求行(request line)，请求数据第一行，包括请求方式GET/POST、资源路径、协议。
      • get：请求参数在请求行中，请求能够携带的参数比较少，大小有限制，会在浏览器的URL地址栏显示数据内容，不安全，但高效。
      • post：请求参数在请求体中，请求能够携带的参数没有限制，大小没有限制，不会在浏览器的URL地址栏显示数据内容，安全，但不高效。
    • 2)请求头/消息头(header)，格式为键值对key: value，包括客户端环境信息、请求体的大小（如果有）、请求的数据格式等。
      • Host：表示请求的主机名。
      • User-Agent：浏览器版本。
      • Accept：表示浏览器能接收的资源类型，如文本text/*，图片image/*或者*/*表示所有。
      • Accept-Language：表示浏览器偏好的语言，服务器可以据此返回不同语言的网页。
      • Accept-Encoding：表示浏览器可以支持的压缩类型，例如gzip, deflate等。
      • Content-Type：请求主体的数据类型。
      • Content-Length：数据主体的大小（单位：字节）。
    • 3)请求体，在请求头和请求体之间存在分隔符空行，表示请求头的结束。请求体可以包括要发送给服务器的数据，请求体并不是必须的，属于可选项。
  • (3)响应协议：
    • 1)状态行(Status Line)，响应数据第一行，包括HTTP协议、状态码、描述状态码的状态。
      • 常见状态码1xx表示响应中：临时状态码。表示请求已经接受，告诉客户端应该继续请求或者如果已经完成则忽略；
      • 2xx表示成功：表示请求已经被成功接收，处理已完成；最经典的为200状态码，表示客户端请求成功。
      • 3xx表示重定向：重定向到其它地方，让客户端再发起一个请求以完成整个处理；
      • 4xx表示客户端错误：处理发生错误，责任在客户端，如：客户端的请求一个不存在的资源，客户端未被授权，禁止访问等；最经典的为404状态码，表示请求资源不存在，或许是URL输入错误也可能是网站资源被删除。
      • 5xx表示服务器端错误：处理发生错误，责任在服务端，如：服务端抛出异常，路由出错，HTTP版本不支持等；最经典的为500状态码，表示服务器发生了不可预期的错误。
    • 2)响应头(Response Headers)，格式为键值对key: value。
      • Content-Type：表示该响应内容的类型，例如text/html，image/jpeg。
      • Content-Length：表示该响应内容的长度，单位字节数。
      • Content-Encoding：表示该响应压缩算法，例如gzip算法。
      • Cache-Control：指示客户端应如何缓存，例如max-age=300表示可以最多缓存300秒。
      • Set-Cookie：告诉浏览器为当前页面所在的域设置cookie。
    • 3)响应体/响应正文，在响应头和响应体之间存在分隔符空行，表示响应头的结束。响应体可以包括响应数据，响应体并不是必须的，属于可选项。
