1.概述

  • (1)概念：Maven是一款基于项目对象模型POM(Project Object Model)的概念，java项目架构管理工具。
  • (2)作用：
    • 标准化（统一）项目结构，简单来说IDEA创建的Maven项目在eclipse中也能运行。
    • 标准化构建流程，Maven提供了一套简单的命令来完成标准跨平台自动化项目构建方式，简化编译、测试、打包、发布。
    • 依赖管理机制：在Java Web开发中，需要使用大量的jar包，Maven工具能做到自动导入和配置jar包，并导入该jar包所依赖的其它jar包，这样还能避免版本冲突问题。同时，我们还会看到war包，和jar包对应java应用一样，war包是针对javaweb应用的。
  • (3)核心思想：约定大于配置，需要什么jar包统一在pom.xml文件中声明导入。

2.Maven安装

  • (1)官网： https://maven.apache.org/
    • .tar对应Linux系统，.zip对应windows系统。
    • Source源码，Binary项目，下载Binary。
  • (2)配置环境变量
    • Win11系统为例：控制面板→系统和安全→系统→高级系统设置→环境变量→选择PATH，在编辑环境变量页面进行添加。
    • 首先，Maven需要在系统配置2个环境变量，一个[MAVEN_HOME]对应到你的放置Maven文件的目录例本机为E:\Code\apache-maven-3.9.11，一个[M2_HOME]对应到你的放置Maven文件目录下面的bin文件夹的路径例如本机为E:\Code\apache-maven-3.9.11\bin。
    • 其次，Path中的环境变量也需要新增，新增一个引用的地址[%MAVEN_HOME%\bin]。
  • (3)使用dos命令确认是否删除成功，cmd进入命令提示符，使用命令mvn -v，如果显示Apache Maven 3.6.2 (40f52333136460af0dc0d7232c0dc0bcf0d9e117; 2019-08-27T23:06:16+08:00)说明安装成功。

4.Maven仓库

  • (1)仓库：管理各自jar包的地方。分为本地仓库、中央仓库、远程仓库。依赖查找的优先度本地仓库>远程仓库>中央仓库。
    • 本地仓库：自己计算机上的一个用来存储jar包的目录（文件夹）。
    • 中央仓库：由Maven团队维护的全球唯一的。
    • 远程仓库（私服）：一般由公司团队搭建的私有仓库。
  • (2)中央仓库地址： https://mvnrepository.com/

5.集成开发环境IDEA中使用Maven

  • (1)在IDEA中创建MavenWeb项目，创建普通的Maven项目，并编辑坐标（Maven中的坐标是资源的唯一标识 , 通过该坐标可以唯一定位资源位置，通过坐标来定义项目或引入项目中需要的依赖，包括groupId、artifactId、version）。
    • Archetype是预置的Maven模板，选择:maven-archetype-webapp
    • groupId/GAV：GroupId组ID，定义项目属性哪个组，通常是域名反写，例如com.retreatafter；artifactId：ArtifactId项目ID，定义在当前组唯一的ID，通常与项目模块名称ProgramName一致，例如order-service、goods-service；version：定义当前项目版本号。
    • directory目录，选择先前Maven配置文件，本机为E:\Code\apache-maven-3.6.2\conf下settings.xml文件。
    • 相关文件路径设置（建议在主界面进行设置，这样为全局设置而不是仅针对当前项目）：
  • (2)创建后会自动导入包，等待项目初始化完毕。
  • (3)Maven在IDEA中存在一个问题，项目自动创建完成后，Maven Home会使用IDEA默认的，因此在项目成功创建之后需要回到设置页面再确认一遍，如果又变成了IDEA默认的则手动改为我们本地下载好的。
  • (4)标记功能，在创建的Maven项目中是无法新建Class文件的，这时就用到标记功能。

6.依赖管理

  • (1)依赖配置：一个项目中可以引入多个依赖，pom.xml是用于放所有依赖dependency的地方。步骤：
    • 1)在pom.xml中编写<dependencies>标签。
    • 2)在<dependencies>标签中使用<dependency>引入坐标。
    • 3)定义坐标的 groupId、artifactId、version。
    • 4)点击右侧Maven列表的刷新按钮，引入最新加入的坐标。
  • (2)依赖传递：依赖具有传递性。
    • 直接依赖：在当前项目中通过依赖配置建立的依赖关系。
    • 间接依赖：被依赖的资源如果依赖其它资源，当前项目间接依赖其它资源。
  • (3)依赖范围：在项目中导入依赖的jar包后，默认情况下，可以在任何地方使用，如果希望限制依赖的使用范围，可以通过<scope>标签设置其作用范围，取值有compile、test、provided、runtime。
    • 主程序范围有效：main文件夹范围内。
    • 测试程序范围有效：test文件夹范围内。
    • 是否参与打包运行：package指令范围内。
scope值 主程序 测试程序 打包（运行） 范例
compile（默认） Y Y Y log4j
test - Y - junit
provided Y Y - servlet-api
runtime - Y Y jdbc驱动
  • (4)生命周期：Maven的生命周期描述了一次项目构建，经历哪些阶段。Maven对项目构建划分为3套相互独立的生命周期，每套生命周期包含一些阶段，同一套生命周期下阶段具有顺序，在执行后面的生命周期时，前面的生命周期都会执行：
    • clean：清理工作。核心关注其中的clean阶段。
    • default：核心工作。如：编译、测试、打包、安装、部署等。核心关注compile、test、package、install阶段。
    • site：生成报告、发布站点等。
