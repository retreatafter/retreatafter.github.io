1.UML

  • (1)定义：UML(Unified Modeling Language)全名叫统一建模语言，又称为标准建模语言，是为面向对象软件设计提供统一的、标准的、可视化的建模语言。
  • (2)UML的词汇表包含3种构造块：事务、关系、图。事物是对模型中最具有代表性的成分的抽象；关系把事物结合在一起；图聚集了相关的事物。

2.事务

  • (1)结构事物：静态，名词。结构事物包括类（Class）、接口（Interface）、协作（Collaboration）、用例（UseCase）、主动类（ActiveClass）、构件（Component）、制品（Artifact）、结点（Node）。
  • (2)行为事物：动态，行为。行为事物包括交互/消息（Interaction）、状态机（StateMachine）、活动（Activity）。
  • (3)分组事物：分组事务是UML模型的组织部分。例如包（Package），结构事物、行为事物甚至其它分组事物都可以放进包内。包与构件（仅在运行时存在）不同，它纯粹是概念上的（即它仅在开发时存在）。
  • (4)注释事物：是UML模型的解释部分。注解（Note）是一种主要的注释事物。

3.关系

  • (1)关联关系(Association)：关联关系是一种结构关系，描述了一组链，链是对象之间的连接。关联用实线（和箭头）表示，可以是单向的也可以是双向的，双向的可以没有箭头（无向边）。关联的多重度是指一个类的实例能够与另一个类的多少个实例相关联。关联类出现在多对多即A的实例可以重复对应B的实例情况，此情况需要创建一个新类关联类来更好的表示AB间的关系。
    • 聚合(Aggregation)：整体和部分生命周期不一致，整体消失，部分仍存在，如班级（整体）与学生（部分）。从代码角度来说，聚合对象是指一个对象包含了其它对象。
    • 组合(Composition)：整体和部分生命周期一致，整体消失，部分也消失，如人（整体）与大脑（部分）。
  • (2)泛化(Generalization)：一般与特殊的关系。在面向对象中称之为继承。泛化用实线和空心箭头表示，例如A-▷B意思为A是B的子类，也可以说基类B泛化出子类A。
    • 单重继承、多重继承（有多个基类）、层级继承（一个基类有多个子类）
  • (3)依赖(Dependency)：依赖是两个事物间的语义关系，其中一个事物（独立事物）发生变化会影响另一个事物（依赖事物）的语义。依赖用虚线箭头表示，例如A----->B意思为独立事务B被依赖事务A依赖，也可以表述为A依赖于B。
  • (4)实现(Realization)：在两种情况下会使用实现关系：一种是在接口和实现它们的类或构件之间；另一种是在用例和实现它们的协作之间。实现用虚线和空心箭头表示，例如A-----▷B，假设此处的B为接口，那么意思为实现类A实现了接口B。

4.UML图分类

  • (1)图的类型：类图、对象图、时序图（序列图/顺序图）、用例图、活动图、状态图、构件图（组件图）、部署图、通信图。
  • (2)静态建模：类图，对象图，用例图。
  • (3)动态建模：序列/时序/顺序图，通信/协作图，状态图，活动图。
  • (4)物理建模：构件/组件图，部署图。
  • (5)交互图：序列/时序/顺序图，通信/协作图。

5.类图

  • (1)定义：类图描述一组对象、接口、协作和它们之间的关系。静态图，为系统的静态设计视图。
  • (2)UML类图建模的对象有：系统的词汇、简单的协作、逻辑数据库模式。
  • (3)注释：+ public - private # protected ~ package

注. https://www.processon.com/view/6502a7869722a31b82da0e21

6.对象图

  • (1)定义：对象图描述某一时刻一组对象以及它们之间的关系。静态图，在没有类图的前提下，对象图就是静态设计视图。
  • (2)特点：对象图和类图有类似之处，而对象图的特点是表示对象的方式为对象名:类名。

7.用例图

  • (1)定义：用例图描述一组用例、参与者以及它们之间的关系。静态图。
    • 参与者是指人、硬件或其它系统可以扮演的角色。
  • (2)用例间关系：（注意，用例图的包含和拓展关系相当于在关联关系上又做了细分，而包含关系中箭头的指向含义和类图相反）
    • 包含include：一个用例包含另一个用例，当基本用例执行时，被包含用例一定会执行。包含关系由基本用例指向被包含用例。关系是一条带箭头的虚线，虚线上标注<<include>>，例如A---<<include>>-->B就表示A包含B。
    • 拓展extend：当一个用例执行时，可能会出现特殊情况和可选情况，这个时候就会执行拓展用例。拓展关系由拓展用例指向基本用例，关系是一条带箭头的虚线，虚线上标注<<extend>>，例如A---<<extend>>-->B就表示B是基本用例，A是拓展用例。
    • 泛化generalize：基用例泛化子用例，子用例继承基用例的所有属性和行为，并且基用例可以出现的地方子用例都可以将其替换。和类图的表现一致，A-----▷B，表示B泛化出A。
  • (3)参与者与用例，就类似对象和对象的行为。关联是参与者和用例之间的关系；包含是用例和用例之间的关系；拓展是用例和用例之间的关系；泛化是参与者和参与者之间的关系也是用例和用例之间的关系。

8.时序/顺序/序列图

  • (1)定义：时序图描述了对象消息发送的先后顺序，强调时间顺序。
  • (2)同步消息：进行阻塞调用，调用者中止执行，等待控制权返回。需要等待返回消息，用实心三角箭头表示。-----▶
  • (3)异步消息：发出消息后继续执行，不引起调用者阻塞，也不等待返回消息，由空心箭头表示。-----▷
  • (4)返回消息：是同步消息的响应。由从右到左的虚线箭头表示。<-----
  • (5)指向对象的如果是方法，那么同时也是这个对象应该实现的方法。

9.通信图

  • (1)定义：通信图展示了对象之间的消息流及其顺序。也是由对象和消息组成的图，只不过不强调时间顺序，只强调事件之间的通信，而且也没有固定的画法规则，和顺序图统称为交互图。
  • (2)更新迭代：自UML 2.0 之后，不再使用协作图，都统一使用通信图。
  • (3)通信图的特点之一是消息具有编号和方向，按照编号来执行。
  • (4)通信图中是用对象表示，:类名不写明对象名说明这是个匿名对象。

10.状态图

  • (1)定义：描述对象在不同状态下的行为与状态转换过程及其事件顺序。转换由事件触发。状态图包括状态、转换、事件、活动。
    • 状态：初态用一个实心黑圆点表示，终态用黑圆点外加一个圆表示。状态图中的状态用一个圆角四边形表示。状态图可以有多个终态，也可以没有终态。
    • 活动：状态图中的状态通常还包括了活动表，也就是活动。在活动表中经常使用下述3种标准事件：entry、exit和do。entry事件指定进入该状态的动作，exit事件指定退出该状态的动作，do事件指定在该状态下的动作。
    • 转换/迁移：带箭头的线。转换包括两个状态。
    • 事件：事件触发转换/迁移，源状态转换到目标状态。语法为事件说明[守卫监护条件]/动作表达式。监护条件只有在相应的事件发生时才进行检查。
  • (2)区别：状态图的箭头会附上监护条件(guard)，而活动图可以带上** “泳道” ** ，因此箭头上没有文字。
  • (3)特点：状态图用于描述一个对象在多个用例中的行为，用于某些具有多个状态的对象而不是系统中大多数或全部对象，可以用于用户界面或控制对象。
  • (4)一个状态中还包含着状态，那么这种状态被称为组合状态/超状态。（图中的ON本身就是一个状态，而在它内部还存在着一系列状态）
  • (5)一个状态转移到多个状态，被称为并发状态。
  • (6)状态图用于对系统、类或用例的动态方面建模时，通常是对反应型对象建模。

//例题
以下UML状态图中，假设活动的状态是A，事件b=0发生并且a>5，发生条件是C状态到D状态的转换条件的是？
解答：状态C内部还有一系列状态，当状态C内部的子状态完成后会查询监护条件，如果满足条件就会转移到D状态，因此一旦状态A和B的所有动作完成，C状态将会转移到D状态。

11.活动图

  • (1)定义：活动图是一种特殊的状态图，描述了完成任务所进行的活动流，也即系统内从一个活动到另一个活动的流程。活动图适合对一个复杂用例中的业务处理流程进行进一步建模。
  • (2)活动图可以带有泳道，但不是必须的。活动图和状态图最大的区别是分支，即图中的菱形。

12.构件/组件图

  • (1)定义：构件图描述了一组构件/组件之间的组织和依赖。静态图，为系统静态实现视图。

13.部署图

  • (1)定义：部署图表示待开发软件系统中软件组件和硬件之间的物理关系。静态图，为系统静态部署视图。它与构件图相关，通常一个结点包含一个或多个构件。其依赖关系类似于包依赖，因此部署组件之间的依赖是单向的类似于包含关系。
  • (2)部署图通常在实施阶段使用。

通信图参考. https://zhuanlan.zhihu.com/p/77813139

14.包图

  • (1)包图（Package Diagram）展现由模型本身分解而成的组织单元以及其间的依赖关系。包可以拥有其它元素，可以是类、接口、构件、结点、协作、用例和图，甚至是嵌套的其它包。一个元素只能被一个包所有，一个包内的元素不能重名。
