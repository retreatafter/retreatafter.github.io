1.概述

  • (1)【重要】Bean声明，即创建对象，使用注解@Component(value = "")，等同于原先配置文件中<bean id="">的功能，value对应bean的id值，此注解的位置写在类的上方，表示为该类创建对象。注解@Component的三个衍生注解，作用上和@Component无区别，仅为更好的区分各个层：
    • @Controller：用于控制器类bean定义。
    • @Service：用于业务层bean定义。
    • @Repository：用于数据层（持久层）bean定义。
  • (2)配置类，组件扫描，声明Bean之后还需要经过组件扫描，来确认扫描（生效）范围：
    • @Configuration：表示这是一个配置类。为配置类创建cglib动态代理并保证单例。
    • @ComponentScan("路径")：用于设定扫描路径。
    • @Import({类名1.class,类名2.class})：用于扫描别的配置类。
  • (3)【重要】自动装配：
    • @Autowired，引用数据类型自动装配，取bean，默认使用byType自动注入。且不再需要setter方法。本质上是在Spring容器中查找Bean的过程。
    • 如果要使用byName方式注入，配合@Autowired使用@Qualifier(value = "bean的id")注解。
    • @Value("值")，基本数据类型自动装配。@Value("${外部文件中定义的属性名}")
    • JDK提供的注解@Resource也可以进行引用数据类型自动装配，原理相同，并且会先使用byName方式注入，若赋值失败，会再采取byType自动注入。
  • (4)作用范围（是否单例）：@Scope()
  • (5)生命周期：
    • @PostConstruct：执行bean设置的初始化方法。
    • @PreDestroy：执行bean设置的销毁方法。
  • (6)加载properties文件：@PropertySource("文件名")。路径仅支持单一文件配置，多文件使用数组格式配置，不允许使用通配符*，即@PropertySource({"com.xxx","com.yyy"})。
  • (7)配置第三方bean：@Bean。

2.基本使用

(1)流程

  • 1)搭建环境。
    • 确保有spring-aop依赖，若导入了spring-context依赖的，其中就包括了spring-aop依赖。
    • 定义类，可能存在接口和对应的实现类。
  • 2)Spring接管。
    • 配置Bean，在需要的地方使用注解。
    • 在spring配置文件中，加入一个组件扫描器标签，说明注解的位置。或使用配置类注解。
  • 3)创建使用测试类。
    • 通过Spring容器对bean进行操作。

3.配置类

  • (1)像@Controller、@Service、@Repository、@Component这些创建对象的注解是由Spring指定对象实例化，进行Bean的注册操作，除了这种自动方式外，还可以使用@Configuration注解使用手工配置方式进行Bean定义，这种方式在创建第三方代码的对象时很常见。
  • (2)创建一个配置类SpringConfig。

public class SpringConfig {

  • (3)注解@Configuration，打上这个注解，表示这是一个配置类，它的内容相当于之前所写的配置文件中的：

       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="http://www.springframework.org/schema/beans http://www.springframework.org/schema/beans/spring-beans.xsd">

</beans>

  • (4)注解@ComponentScan("src.main.com.retreatafter")打上这个注解，用于设定扫描路径，它的内容相当于之前所写的配置文件中的：<context:component-scan base-package="src.main.com.retreatafter"/>

    • 这个注解只能添加一次，如果有多个数据，采用数据格式，例如：@ComponentScan({"src.main.com.retreatafter.dao","src.main.com.retreatafter.service"})。
